# Clanker vs Pons

These two get mentioned in the same breath because both are agent-facing onchain services on Base, and the comparison usually starts from a false premise: they are not competitors. The directory classifies them differently, and that difference — visible in the first row of the table — is the answer to most questions people bring here.

So read this page as a disambiguation rather than a shootout. The table shows what each is, who maintains it, how open it is, and what evidence we hold for either. Every cell is read live from the directory, so it says what the record says today and nothing more.

## Pick Clanker if

- You want an agent-operated token deployment path on Base with an established public footprint.
- You are working inside the Farcaster/Base surface where its deployments already sit.
- You want a launch venue with a documented interface an agent can call, rather than a UI flow.

## Pick Pons if

- You are working on the DeFi tooling side rather than the launch side — the first row of the table is the whole distinction.
- You want the project whose category and interfaces match a DeFi integration, not a deployment.
- You prefer the newer, narrower surface over a broader launch product.

## What this cannot settle

This pair spans two different categories, so several rows compare things that are not alike — a launch venue and a DeFi tool can share a chain and share nothing else. Nothing here is a measurement of token outcomes, deployment safety, or what happens to anything either one launches or touches: the directory records what each project is and how maintained it is, not what using it results in. Neither has an earned verification that would say otherwise.
