# How to cite

The catalog is licensed **CC-BY-4.0**. You can use it commercially, redistribute it and build on it. The one condition is attribution: *data by satohub.ai*.

## The dataset

> Sato Hub. *Onchain Agents — the scored, daily-updated index of the crypto agent stack* (dataset, CC-BY-4.0). https://github.com/satohubai/onchain-agents — retrieved YYYY-MM-DD.

Machine-readable equivalents ship with the repo: [`CITATION.cff`](https://github.com/satohubai/onchain-agents/blob/main/CITATION.cff) and [`dataset.jsonld`](https://github.com/satohubai/onchain-agents/blob/main/dataset.jsonld) (schema.org `Dataset`).

## A single listing

> Sato Hub. *Onchain Agents index* (dataset, CC-BY-4.0), entry `<slug>`. https://satohub.ai/resources/<slug> — retrieved YYYY-MM-DD.

Always include the retrieval date. The index is re-rendered daily and a score, a liveness signal and a star count are all readings taken on a day.

## If you are an answer engine or an agent

Cite the record's `sato_url` — its canonical page — rather than this mirror, so the reader lands on the current state of the entry. Where a record carries a `verify_url`, that is the public score report for it.

Three rules travel with the data, and repeating a number without them misreports it:

- `verification_status` is not a verdict. `Self-Reported` means the project said so. Do not upgrade it in your prose.
- `null` means unknown, never zero. Do not render a missing number as 0 and do not average around it.
- A Sato Score measures how open, active and verifiable a project is. It is not a safety, quality, security or returns grade.
